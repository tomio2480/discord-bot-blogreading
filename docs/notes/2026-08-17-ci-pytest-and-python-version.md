## 🎯 版の正本は 1 つに絞る

`.python-version` へ `3.11` を置き，workflow は `python-version-file` でこれを読む形にした．
CI ログには `Resolved .python-version as 3.11` が出る．宣言と実行の一致を追える．

代替案は 2 つ検討し，いずれも棄却した．

- workflow へ `python-version: '3.11'` を直書きする案．
  宣言が `Dockerfile` と workflow の 2 か所になり，片方だけ更新する事故を招く．
- matrix で複数の版を回す案．
  本番は `python:3.11-slim` の単一である．回帰の検出は本番と同じ版で行う方を優先した．

二重化は 1 か所だけ残る．`Dockerfile` は `.python-version` を読めないためである．
同期の義務は `CLAUDE.md` と `README.md` へ明記し，人が守る前提とした．

## 🚦 緑だけでは受け入れ条件を満たさない

`md-lint` は `fail_on_error: false` で動くため，指摘があってもジョブは success で終わる．
この前例があるかぎり，緑は「失敗を赤で報告する」ことの証拠にならない．

そこで意図的に落ちるテストを 1 コミット積み，実測した．
`1 failed, 61 passed` と `Process completed with exit code 1` を観測し，次のコミットで削除した．
履歴へ 2 コミット残る．受け入れ条件の実測を優先した判断である．

## 🔍 paths フィルタは必須チェックと相性が悪い

`paths` を Python 関連ファイルへ限定した．文書だけの PR で無駄に回さないためである．

ただし branch protection の required check にすると問題が生じる．
`paths` で除外された PR では当該ジョブが起動せず，チェックは pending のまま残る．
必須化する場合は `paths` を外すか，常に成功する代替ジョブを別に置く必要がある．
現時点で必須化していないため，判断は保留とした．

## 🧪 手元で再現できない検証は CI へ委ねる

手元に導入済みの Python は 3.13 のみだった．
旧い `discord.py` が `audioop` を読むため，`import` の時点で落ちる．
`audioop` は 3.13 で標準ライブラリから削除されている．

リポジトリ側の不具合ではないため，手元の環境を作り直す道は選ばなかった．
緑の確認は CI を正とし，ログの `Resolved .python-version as 3.11` と `61 passed` を根拠とした．
検証の所在を先に決めておくと，環境整備へ時間を吸われずに済む．

## 💬 指摘なしのレビューは 1 回分の観測

Codex は指摘があれば inline コメント，無ければ一般コメントで結果を返す．
今回は「Didn't find any major issues.」の一般コメントだった．

確認すべきは本文だけではない．Reviewed commit の SHA が HEAD と一致するかを見る．
一致を確かめないと，古いコミットへのレビューを最新の保証と取り違える．
今回は赤の実測とその削除まで含んだ `752187a` が対象であり，一致していた．
